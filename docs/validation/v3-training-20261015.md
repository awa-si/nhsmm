## Change and ownership

NHSMM.optimize remains the public fitting boundary and returns its model.
Its orchestration now lives once in nhsmm/training.py: optimizer/scheduler
construction, independent restarts, convergence, history/update ordering and
post-update restart selection. models/base.py shrinks from 1840 to 1684 lines;
the new training module has 184 lines. This is separation of ownership, not a
claim that total source size decreased or runtime became faster.

Model-specific initialization, loss, batching, snapshot and transition-refinement
helpers remain on the model. Existing tests, diagnosis scripts and subclasses
call those hooks, so this batch keeps that established boundary rather than adding
a parallel compatibility layer or mixin. There is one optimizer loop.
Configuration defaults, API behavior, artifact/state_dict keys, parameter
registration, dtype/device behavior and core NumPy/PyTorch-only dependencies
remain unchanged. The core does not import Qlib.

History still records pre-update scores. completed_updates describes main
updates preceding that score; one optimizer step follows each history entry.
Final restart scores describe post-main-update parameters, before optional
transition refinement. Selection, tail projection and restoration of caller mode
retain their order. A failure restores mode without rolling back finished updates.

## Exact baseline replay

The pre-refactor model module was copied before source edits and its SHA256 is
10f4ca09722d06423ed1bd3361ec268316f9fdb39ccc0882a9f86e78e4c705da.
Eight small deterministic synthetic scenarios compare that module with the new
public optimize entry point in the same runtime (Torch 2.14.1+cpu, one thread).
Parameters/state_dict, Adam state, histories, restart scores, convergence and
scheduler state, best snapshots, final likelihood, changed parameter names and
the final PyTorch RNG state match with tolerance exactly zero, including paired
NaNs in unobserved convergence slots.

| Scenario | Main updates per implementation | Refinement updates | Exact match |
| --- | ---: | ---: | --- |
| Constant-temperature independent restarts | 6 | 0 | yes |
| Annealed restarts and scheduler setup/state | 6 | 0 | yes |
| Internal neural context with dropout | 6 | 0 | yes |
| External context and transition refinement | 6 | 2 | yes |
| D+ tail with chunking and an empty sequence | 6 | 0 | yes |
| Noncausal completed-segment objective | 6 | 0 | yes |
| Float64 current initialization with frozen components | 3 | 0 | yes |
| Actual plateau early stopping | 4 | 0 | yes |

The early-stop case explicitly uses a permissive plateau tolerance and stops
after two updates per restart from an eight-update budget. The first replay used
the delta tolerance with the default plateau mode and therefore consumed the full
budget; the final replay corrects the probe configuration, not production code.
Scheduler setup/state is covered here; this short probe does not claim to exercise
a learning-rate reduction.

Per-case source/state hashes and raw timings are recorded in the companion JSON.
Timings include cold initialization and overlapping test work. They are not a
controlled benchmark and support no speedup claim.
