## Applied behavior-preserving hardening

- `DefaultEncoder.forward()` moves provided masks to the input device.
- `SequenceSet.from_unbatched()` and `SequenceSet.batchify()` allocate helper tensors on the sequence device.
- `SequenceSet.select()` / `ContextRouter.select()` / `select_features()` create index tensors on the source tensor device.
- `ContextRouter` creates its default mask on the context device.
- `ContextEncoder` creates/defaults masks on the input device.
- `_last_timestep()` creates batch indices on the context device.
- lazy attention/MHA objects are created on the active context dtype/device.
- temporary `pool=` overrides in `ContextEncoder.encode()` and `SequenceSet.update()` are restored with `try/finally`.
- an unused `logger` import was removed from `encoder.py`.
- focused CPU/CUDA-conditional regression coverage was added in `tests/test_context_hardening.py`.

These changes do not alter CPU probabilistic semantics, transition/duration math, training objective, causal boundary ordering, public validation thresholds, or artifact schema.

## Open findings

### P0 — advertised Python 3.9 support is inconsistent with source syntax

`pyproject.toml` declares `requires-python = ">=3.9"`, includes a Python 3.9 classifier, and configures Ruff/Black/mypy for 3.9. Current source and scripts use PEP 604 union syntax such as `float | torch.Tensor`, `torch.Tensor | None`, and `dict[str, int | float]`.

PEP 604 union syntax requires Python 3.10+ parsing. `from __future__ import annotations` does not make this syntax parse on Python 3.9.

Decision required:

1. preserve Python 3.9 support and convert incompatible annotations to `Union` / `Optional`; or
2. raise the package/runtime/tooling contract to Python 3.10+ and remove the 3.9 classifier/targets.

No compatibility policy was changed during this scan.

### P0 — `SequenceDataset(variable_length=True)` is structurally inconsistent

`generate_gaussian_sequence()` returns one observation tensor, one state tensor, and one context tensor. The `variable_length=True` branch wraps observations and contexts in lists but leaves `states` as the flat state tensor. `__getitem__()` therefore returns a scalar state for an item while `collate_fn()` expects a state sequence and passes the values to `pad_sequence()`.

No maintained test currently covers this path.

The intended meaning of `variable_length` needs to be defined before changing behavior: segmentation policy, number of sequences, state/context alignment, and reproducibility all need an explicit contract.

### P0 — attention/MHA pooling lifecycle is incompatible with restart training

`ContextEncoder` lazily creates `_attn_vector` and `_mha`. `NHSMM._initialize_run_state()` restores the encoder state and then calls `encoder.reset()`, which sets those lazy trainable objects to `None`. The optimizer parameter list is collected after reset; the attention/MHA parameters are then recreated only on the first forward pass and are therefore absent from that optimizer.

Consequences when `pool="attn"` or `pool="mha"` is used for training can include:

- recreated pooling parameters not being optimized;
- restart state not preserving those pooling parameters as intended;
- state-dict/lifecycle behavior depending on whether a forward pass has already occurred.

This requires a lifecycle design change (eager module construction or reset semantics that preserve trainable pooling state), so it was not changed in a behavior-preserving scan.

### P1 — core data module contains a trading-specific loader

`nhsmm/data.py::load_dataframe()` hardcodes a Freqtrade futures Feather filename convention and error text. Repository search found no core consumer of this helper.

This is inconsistent with the package's universal modeling scope and appears to be the only core reason for the `polars` runtime dependency. A separate decision should determine whether to move it to an integration/example layer, make it optional, or retain it as supported API.

### P1 — explicit 2-D context semantics are inconsistent

`NHSMM._build_sequence_set()` treats 2-D explicit context as time-major `[T,H]` and expands it over the batch. `ContextRouter.from_tensor()` separately supports both `[T,H]` and `[B,H]`.

The public model path therefore does not share the router's full 2-D context contract. A shape-disambiguation rule is required before changing this behavior.

### P1 — invalid optimization configuration fails late

`ModelConfig` does not validate several optimization-domain constraints. Examples include `n_init <= 0` and `max_iter <= 0`; these can produce no-run behavior or late/unbound failures in `optimize()` rather than an early configuration error.

Validation should be added only after defining which values are supported API.

### P1 — transition refinement without context has no explicit guard

When `transition_refine_steps > 0` but no transition context network exists, transition refinement accesses `transition.context_net.parameters()` without a dedicated contract check. The resulting failure is implementation-shaped rather than a clear configuration error.

### P2 — base `DistributionSet` ignores injectable distribution-class arguments

`nhsmm.models.base.DistributionSet.__init__()` accepts `initial`, `duration`, `transition`, and `emission` arguments but instantiates the hard-coded default classes instead. The canonical training `DistributionSet` honors these arguments. This makes the base extensibility signature misleading.

### P2 — artifact construction mutates model mode

`build_artifact()` calls inference preparation, which switches the supplied model to eval mode. Current tests exercise artifact construction from an already-eval model, so the side effect is not covered. A decision is needed whether artifact creation should be observational or intentionally inference-preparing.

### P2 — cached context tensors retain graph/lifecycle state

`ContextEncoder.forward()` stores `_sequence` and `_context` tensors. These caches can retain autograd graph state and were the underlying reason `copy.deepcopy(NHSMM)` was not a valid test cloning strategy. They are internal today; their lifecycle can be simplified later if no supported consumer requires them.

### P2 — remaining hygiene

- `nhsmm/distributions/default.py` still imports unused `Independent` and `logger`.
- `Emission.log_prob()` uses `assert torch.isfinite(logp).all()`. Assertions disappear under `python -O`; explicit runtime validation would give invariant behavior.
- `ModelConfig.emission_init_mode` types the legacy misspelling `"randome"`, while implementation maps it to `"random"`; the correctly spelled value is not part of the declared Literal.
- library-level logging configuration is installed from `config.py`, which may be more policy than a reusable package should own.

These were left unchanged to keep this pass behavior-preserving and narrowly scoped.

2. define/fix `SequenceDataset(variable_length=True)`;
3. fix attention/MHA pooling lifecycle for training/restarts;
4. decide whether trading-specific data I/O belongs in the core package;
