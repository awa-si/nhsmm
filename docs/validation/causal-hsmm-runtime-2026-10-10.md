# Causal HSMM runtime optimization — 2026-10-10

## Investigated optimization (not merged)

A proposed age-first reduction for duration-independent transitions avoids
materializing a `(batch, state, duration, next_state)` intermediate.
The production implementation was **not changed**, because the end-to-end
benchmark did not demonstrate a speedup.

The reduction is mathematically equivalent; floating-point reduction order
changes. In an isolated CPU benchmark (batch 24, 4 states, duration 64,
100 forward/backward steps), old 0.104 s versus new 0.036 s (~2.9x speedup),
maximum absolute forward discrepancy 4.77e-7. This is a microbenchmark, **not**
a measured end-to-end speedup.
