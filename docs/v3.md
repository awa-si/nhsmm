## Core refactoring order

1. Causal recurrence — batch 1 complete: forward and streaming/filter share
   initialization, state-age propagation and normalized-frontier/evidence output.
   Independent probability-space path enumeration checks posterior, evidence and
   gradients, alongside the maintained reference suite. Boundary timing,
   self-renewal, D+ tails, impossible support and variable-length masking remain
   intact. Causal censored-prefix and noncausal completed-segmentation objectives
   remain distinct. See [batch evidence](validation/v3-causal-frontier-20261015.md).
2. Training ownership — batch 2 complete: the public optimize method delegates
   to a single orchestration function in nhsmm/training.py. It owns optimizer/
   scheduler setup, independent restart control, convergence, update/history
   ordering and final restart selection. Initialization, model-specific objective
   and snapshot helpers remain on the model; their existing consumers keep the
   same boundary. No mixin, duplicate training loop or compatibility helper layer
   was introduced. Eight exact pre/post-refactor replays and failure-boundary
   regressions validate the move. See [batch evidence](validation/v3-training-20261015.md).
   The public optimization_summary now exposes independent completed-fit update
   telemetry for host consumers; failed subsequent fits invalidate prior telemetry.
3. Configuration/context — batch complete: external list alignment has one
   context-module owner and reuses validated observation lengths/masks. Empty
   contexts retain [B,1,H] canonical shape. Config mapping construction shares one
   parser; strict errors and explicit permissive filtering are retained. Defaults
   and positive-length context timing remain unchanged. See
   [validation](validation/v3-config-context-20261015.md).
4. Evidence cleanup — batch complete: original reports/proofs/batch bytes are
   bound by a Git-anchored historical evidence index. Metadata-only archive audits
   and strict numerical replay are separate APIs/modes. Historical negative tests
   use the matching audit boundary; numerical replay still rejects software drift.
   Full pytest now runs without the five exclusions. Old evidence is unchanged.

Each batch requires syntax/static checks, focused reference/invariant/gradient
checks, material consumer verification and the broader suite for shared inference
or training changes. Record exceptions explicitly. Measure runtime changes on the
same representative workload; do not relax tolerances to obtain equivalence.

## Validation-path audit

The validation package now rejects negative transition mass, silently discarded
batch/time axes, non-integer splits, reused replica objects and empty state
effects. Constant context effects cannot pass selection at zero thresholds.
Callback arrays are captured immediately; Pearson correlation, assignment
potentials, mass normalization and direction comparisons avoid preventable
overflow. Component probes and snapshots restore mixed submodule modes on
success and failure. Split-fit preparation has one owner.
Final gates: 74 focused tests, 44 installed regressions and 84 host tests.
See [audit evidence](validation/v3-validation-path-20261015.md).
Replication checks remain descriptive; caller-owned temporal separation,
preprocessing and seed/weight independence are not inferred from array slices.
Oracle remains OFF and the frozen late holdout is unchanged.

## Maximum useful Qlib reuse

Integration owner: awa-si/nautilus, adapter/qlib. The model core keeps its existing
NumPy/PyTorch dependency boundary. Qlib owns research orchestration around the
core; Nautilus owns market provenance and execution.

| Need | Reuse / next extension |
| --- | --- |
| Frames, slicing, preprocessing | Existing StaticDataLoader, DataHandlerLP and DatasetH boundary; fit processors on training only. |
| Dataset alignment and supervised purging | Existing adapter/qlib/dataset.py; preserve exact indices, cadence, observation schema and label maturity. |
| NHSMM training | Implemented host NHSMMModel calls public optimize/optimization_summary on train-only feature sequences, grouped by instrument and contiguous cadence segment. |
| Regime outputs | Existing artifact-only regime_features plus implemented NHSMMModel.predict return causal, indexed post-fit regime features with explicit provenance. |
| Experiment tracking | Implemented NHSMMRecord uses Qlib R/Recorder and local MLflow for config/source/data hashes, actual updates, core health and sealed artifacts. |
| Regime evaluation | Implemented NHSMMRecord reuses core likelihood/health, occupancy, duration and transition diagnostics. No ground-truth boundary-accuracy claim. |
| Supervised challengers | Existing real Qlib LGBModel with base versus base+NHSMM ablation; standard signal analysis applies to actual prediction scores. |
| Rolling / multiple seeds | Reuse Qlib task configuration, RollingGen and recorder collection where calendar semantics fit the declared cadence. Audit generated fold bounds before execution. |

The original artifact-only regime_features bridge remains inference-only.
The host now also supplies make_feature_dataset, real Qlib NHSMMModel fitting and
NHSMMRecord. The shared make_dataset still consumes supervised labels/maturity;
the separate feature-only path creates no fabricated targets or maturity purge.
Both reuse the same split validation and real Qlib data primitives. Predictions
start cold per instrument/contiguous run and must be strictly post-fit. External
context, learned processors and cross-fold alignment are not silently inferred.

Do not apply cross-sectional IC/portfolio defaults to latent state identifiers.
Ground-truth regimes remain evaluation-only. Preserve sequence continuity,
per-instrument state, train-only fitted transforms, past-only context, fold-local
artifact provenance and explicit state alignment between independently fitted
folds. Qlib does not establish those HSMM-specific guarantees automatically.

Prefer a small declarative Qlib task and recorder over another custom experiment
scheduler or one-off training script. Keep package imports configurable and model
serialization explicit: Qlib Model's learned attributes must survive serialization;
persist and verify the core's own artifact/provenance contract as well.
